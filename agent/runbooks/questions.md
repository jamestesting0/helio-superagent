# Human questions

## Human questions through Discord (commands and recovery)

Use `helio question ask --lane KEY --audience owner|staff|thread [--recipient USER_ID] --text "..."`, run as an argv array. For a choice add `--option TEXT` 2-5 times; each is a button and one tap answers. Ask a yes/no question with `--option Yes --option No`. A custom answer is a reply to the question message: it is recorded and the buttons are cleared. Both arrive as `QUESTION_ANSWERED`. An unanswered question expires after 72 hours with `QUESTION_EXPIRED` (`helio question show ID`): continue with your recommendation if the work is reversible, otherwise report the open decision once; expiry approves nothing. Ask one decision per question; owner-only decisions (deploys, credentials, policy, money) go separately to the owner DM. For merge or restart approval the lead uses `--action` instead (oracle-restart-workflow.md, "Button confirmations"); its decision arrives as `INBOUND_CONFIRM`, not `QUESTION_ANSWERED`. Use `lead` as KEY for lead work. Every ask states who must hear the answer: `--for TOPIC` (the anchor message of the requester's conversation) when you ask the owner or staff on someone's behalf, otherwise `--internal REASON` (for example the requester answers it themselves, or an owner-only matter). The command durably records the question before sending it and gives the recipient a message to reply to. Start a persistent `helio question watch --lane KEY` monitor with filter `^QUESTION` before asking; keep it active while working. Each lane handles only its matching question IDs; the lead coordinates if a worker is gone or its watcher failed. Read the full question and answer with `helio question show ID`, following its read_more pages; these include the top-level sender, role and scope. Recheck the current trust list and retain all PR/merge/restart confirmation and release-check requirements; a response to a question does not automatically authorize other actions. Run `helio question ack ID` only after the answer has been handled or durably relayed to the right lane; do not acknowledge an unanswered question. For a `--for` question, handling means telling the requester the decision in plain words in their conversation with `--event question-QID`, then `helio conversation close TOPIC OUTCOME`; the ack is refused until that reply is recorded, and `--no-relay REASON` records why someone must not hear it.

If delivery fails, retain the question and report `QUESTION_DELIVERY_ERROR` to the lead. A `queued` question was not sent and can be sent with `helio question retry ID`; retry `send_failed` only after resolving the cause. If an unsent question needs rerouting, `helio question cancel ID` retires the known-unsent question before creating the replacement. A sent question that no longer matters (a policy change or an answer from elsewhere settled it) is retired with `helio question withdraw ID`; if the person may still be about to answer, tell them once that it is no longer needed. A `sending` state that persists is uncertain, not permission to resend. For `sending` or `delivery_unknown`, first use `helio question recover ID` to check recent messages; do not blindly resend an uncertain delivery. A question without a confirmed answer stays pending across restarts until it expires after 72 hours (`QUESTION_EXPIRED`). Never turn elapsed time or expiry into approval. The user must reply directly to the question message so it can be matched safely. If an answer arrives before sending is confirmed or a recording warning occurs, use `helio question reconcile` before acknowledging that inbound message.

Custody questions (lane `custody-issueN`) are asked by the PR controller, not by you or a worker: each names one
decision with the recommended option first. Apply an answer only with `helio pr phase decide --issue N --question
QID` (see issue-plan-workflow.md, "Custody events"); `helio question ack` refuses them. A worker's open question may
be moved to that lane with `helio question transfer QID --lane custody-issueN` so the idle worker's slot is released;
its answer then clears the worker's blocker through the same `decide` command.
